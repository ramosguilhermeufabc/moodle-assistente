# Prompt 3 — Execute Plan Using Specs as the Sole Context

## Objective
Generate the Spec Kit planning artifact (`plan.md`) from the project's existing specifications only. This phase is exclusively the **Plan** phase.

## Required preconditions
- Prompts 1 and 2 completed successfully and were reviewed.
- Claude integration is verified.
- The 23 files under `specs/*/spec.md` are present.

## Sole-context rule
For all project-specific requirements, assumptions, scope, constraints, behaviors, and acceptance criteria, **the 23 `specs/*/spec.md` files are the sole source of context**. Do not import requirements or assumptions from `requirements-traceability.md`, `source-audit-66.md`, `decision-register-DEC-01-25.md`, `decision-propagation.md`, `research.md`, `install_auditado.xml`, conversation history, GitHub, or general model knowledge. Those sources must not be used to fill gaps in the plan. If a necessary detail is absent or contradictory in the specs, record it as an explicit open question/risk; do not resolve it by inference.

## Scope and isolation
- Run only the official Spec Kit Plan workflow (the installed Claude command corresponding to `/speckit.plan`).
- Read the existing specs as input; produce/update only the plan artifacts required by this phase, such as `plan.md` and any plan-specific research/design artifact explicitly generated by the official workflow.
- Do not run `/speckit.tasks`, `/speckit.implement`, or equivalent task/implementation workflows.
- Do not rewrite the specs in this phase.
- Do not edit plugin code, XMLDB, or `install_auditado.xml`.
- Do not search or scan GitHub project repositories.

## Plan requirements
1. Identify the spec files used as input and cite their paths in the plan where relevant.
2. Derive technical approach, dependencies, phases, and validation gates only from the specs.
3. Separate explicit requirements from planning choices and label planning choices as such.
4. Where the specs do not support a decision, preserve the uncertainty as a blocker/open question.
5. Do not claim technical compatibility has been tested unless the plan phase actually ran a documented test.

## Completion criteria
Report:
- exact command used;
- plan artifacts created/changed;
- spec files used as the sole project context;
- open questions/contradictions found in the specs;
- confirmation that no tasks or implementation were executed and no plugin/schema files were changed.

Stop after Plan. Wait for explicit review/authorization before Prompt 4.
