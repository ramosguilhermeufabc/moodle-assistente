# Prompt 4 — Generate Tasks Using Specs and Plan Artifacts

## Objective
Generate the Spec Kit task list (`tasks.md`) using the project specs and the artifacts produced by the reviewed Plan phase. This phase is exclusively the **Tasks** phase.

## Required preconditions
- Prompts 1–3 completed successfully and were reviewed.
- Claude integration is verified.
- The 23 files under `specs/*/spec.md` are present.
- The Plan artifacts (`plan.md` and any official plan-phase artifacts) exist and have been reviewed/approved.

## Allowed context
Use only these project-specific sources:
1. The 23 `specs/*/spec.md` files.
2. The artifacts generated by Prompt 3's Plan phase, including `plan.md` and any plan-phase artifacts that were explicitly produced and approved.

Do not use `requirements-traceability.md`, `source-audit-66.md`, `decision-register-DEC-01-25.md`, `decision-propagation.md`, `research.md`, `install_auditado.xml`, conversation history, GitHub, or general model knowledge to add or resolve project requirements. If an approved spec or plan artifact does not answer a question, record it as a task dependency/blocker; do not invent a resolution.

## Scope and isolation
- Run only the official Spec Kit Tasks workflow (the installed Claude command corresponding to `/speckit.tasks`).
- Produce/update `tasks.md` and only the task artifacts explicitly required by that workflow.
- Do not rerun Plan or rewrite the specs in this phase.
- Do not run `/speckit.implement` or start coding.
- Do not edit plugin code, XMLDB, or `install_auditado.xml`.
- Do not search or scan GitHub project repositories.

## Task requirements
1. Derive tasks and ordering from the specs and approved Plan artifacts.
2. Link each task to the relevant spec section and plan dependency where possible.
3. Include verification/test tasks only when grounded in the allowed sources; distinguish planned verification from tests already executed.
4. Preserve unresolved dependencies as explicit blockers, not silent assumptions.
5. Do not claim complete requirement coverage unless every requirement represented in the allowed sources is mapped to a task or explicitly marked blocked with a reason.

## Completion criteria
Report:
- exact command used;
- task artifacts created/changed;
- mapping from tasks to spec paths and plan artifacts;
- blocked/unmapped requirements and reasons;
- confirmation that implementation was not run and no plugin/schema files were changed.

Stop after Tasks. Wait for separate authorization before any implementation or additional analysis phase.
